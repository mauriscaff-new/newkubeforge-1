Guia de Estudos: Docker e Kubernetes

Docker resolve empacotamento e consistencia de ambiente. Kubernetes resolve operacao em escala, alta disponibilidade, rollout e autoscaling. Estude primeiro o ciclo de vida do container, depois o ciclo de vida do pod e o loop de reconciliacao do cluster.

Sequencia recomendada: Docker basico -> Dockerfile e multi-stage -> Compose local -> objetos K8s -> operacao (logs, debug, rollout, scaling).

1. Docker Essencial

Conceitos

  • Image: template imutavel com camadas.
  • Container: processo isolado executando uma image.
  • Registry: repositorio de images (Docker Hub, GHCR, ECR, GCR).
  • Volume: persistencia de dados fora do ciclo de vida do container.

Camadas e cache

A ordem do Dockerfile impacta tempo de build. Copie arquivos de dependencia antes do codigo para preservar cache em RUN npm ci ou RUN pip install. 

FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
CMD ["python", "main.py"]

Comandos basicos

docker build -t minha-api:dev .
docker run --rm -p 8000:8000 minha-api:dev
docker ps
docker logs -f <container_id>
docker exec -it <container_id> sh

2. Dockerfile e Multi-stage Build

Padroes recomendados

Base pequena

Use alpine ou slim quando possivel.

Usuario nao-root

Reduz impacto de comprometimento.

CMD em JSON

Melhor tratamento de sinais (SIGTERM/SIGINT).

.dockerignore

Evita build lento e vazamento de arquivos sensiveis.

Exemplo multi-stage (Node)

FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM node:20-alpine AS runner
WORKDIR /app
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/package*.json ./
RUN npm ci --omit=dev
CMD ["node", "dist/main.js"]

3. Docker Compose

Compose e ideal para ambiente local com varios servicos (app, banco, redis, fila). Os servicos se enxergam pelo nome do servico na rede interna. 

services:
  app:
    build: .
    ports:
      - "8000:8000"
    depends_on:
      - redis
  redis:
    image: redis:7-alpine

Comandos uteis

docker compose up --build
docker compose ps
docker compose logs -f app
docker compose down -v

4. Arquitetura Kubernetes

Componente Papel Ponto de estudo
API Server Entrada de todas as operacoes Entender modelo declarativo e recursos.
etcd Estado do cluster Consistencia e persistencia do estado desejado.
Scheduler Escolhe node para pods Requests/limits, afinidade, taints.
Controller Manager Reconcilia estado real x desejado Deployments, replicas e autorecovery.
Kubelet Agente no worker node Health checks e status dos pods.

5. Objetos Kubernetes que voce precisa dominar

Pod e Deployment

Pod e a menor unidade de execucao. Deployment gerencia replicas, rollout e rollback.

Service

Fornece endereco estavel para pods efemeros. Tipos mais usados: ClusterIP, NodePort e LoadBalancer.

ConfigMap e Secret

ConfigMap para configuracao nao sensivel. Secret para dados sensiveis. Em producao, combine com ferramentas como External Secrets ou Vault.

HPA

Horizontal Pod Autoscaler aumenta/reduz replicas por metrica (CPU/memoria/custom).

Kustomize

kubectl apply -k .
kubectl diff -k .

6. Seguranca em containers e cluster

Imagem minima

Menos pacote = menos CVE.

Nao-root

Defina usuario sem privilegio no container.

NetworkPolicy

Negue por padrao e abra so o necessario.

Segredos externos

Nao dependa apenas de base64 em Secret.

Regra pratica: todo container deve ter minimo privilegio de rede, sistema e credenciais.

7. Observabilidade e operacao

Comandos de diagnostico K8s

kubectl get pods -A
kubectl describe pod <pod> -n <ns>
kubectl logs <pod> -n <ns> --previous
kubectl top pods -n <ns>
kubectl rollout status deployment/<name> -n <ns>

Sinais comuns de problema

  • CrashLoopBackOff: processo principal falhando ao iniciar.
  • ImagePullBackOff: erro de registry/tag/credencial.
  • OOMKilled: limite de memoria baixo.
  • Readiness falhando: app nao pronta para trafego.

8. Laboratorio guiado (passo a passo)

  1. Crie um app HTTP simples e containerize com Dockerfile.
  2. Adicione healthcheck e rode localmente com Compose.
  3. Suba em kind/minikube com Deployment + Service.
  4. Inclua probes de liveness/readiness e force falhas controladas.
  5. Configure HPA e gere carga para observar scaling.
  6. Aplique NetworkPolicy e valide trafego permitido/bloqueado.
  7. Use Kustomize para variar dev/stage/prod.
